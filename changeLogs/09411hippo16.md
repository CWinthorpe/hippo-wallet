# v0.94.11-hippo.16 — Rabby v0.94.11 security line

Ports the RabbyHub/Rabby v0.94.11 stable release (range a3084ea2d..a5f3af383,
16 commits) with Hippo's privacy and product-surface invariants preserved.

Security-relevant fixes:
- #4135 (17baa3a31) closes a signing/approval mismatch on Tempo (EIP-0776)
  multi-call transactions: previously, when the approval result omitted a call
  field, the background controller backfilled `to`/`data`/`value` from the
  dapp-supplied request and signed the merged result, so a keyring could sign
  call fields the user never saw or approved. Now only the exact approved call
  fields are signed, missing fields stay missing, and an approval carrying no
  calls at all is rejected ("tempo transaction has no approved calls").
  Upstream regressor `__tests__/background/tempoSigning.test.ts` is ported and
  pinned on Hippo: it verifies field-by-field that removing a field from the
  approval is never restored from the dapp request, and that an empty approval
  fails closed without reaching `keyringService.signTransaction`.
  Hippo adaptations (no security assertion dropped): the upstream mock of the
  removed `@/background/utils/gasAccountLogin` module is dropped (module does
  not exist in Hippo), and the `isGasAccount` parameterization is narrowed to
  `false` because Hippo rejects gas-account/sponsored/gasless submission
  fail-closed before signing — a dedicated Hippo test pins that rejection
  (both `isGasAccount` and `isGasLess` throw, signing never called).
- #4132 (ed9083c25) caps dapp-provided `tx.gas` in `calcGasLimit` at
  min(block gasLimit, per-chain single-tx limit); previously an over-limit
  `tx.gas` passed through untouched, producing an unminable transaction whose
  inflated gasLimit x price could also fail the native balance check.
  Invalid (NaN) values now fall back to our own estimate. Ported verbatim with
  its upstream test.

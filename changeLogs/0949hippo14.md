# v0.94.9-hippo.14 — Rabby v0.94.9 security line

Ports the RabbyHub/Rabby v0.94.9 stable release with Hippo's privacy and
product-surface invariants preserved.

Security fixes:
- #4100 binds every approval settlement to its originating request:
  `resolveApprovalFor`/`rejectApprovalFor` require a full {id, component} ref,
  validated before any state mutation; `useApproval` bindings are mandatory and
  fail closed; Unlock settles from an event-captured ref instead of whatever is
  current at broadcast time; the ImportAddress approvalId chain is threaded
  end-to-end; waiting pages settle before unmount. Closes the
  approval-ID/component-confusion class on upstream's consent path.
- #4105 aligns the Tempo signing-display transaction with the submitted
  transaction (buildSignTx now applies the same Tempo normalization used at
  submission, so what the user sees is what gets signed).

Also from the stable line: #4110 spender display-list update (incl. two
revocations), #4109 additional EIP-7702 revoke chains, #4103 Safe queue action
label fixes, #4112 bounded bootstrap-timeout reload fallback (rebranded),
style/data-only changes.

Not ported (Hippo policy): #4098 extension auto-update notifications
(rabby.io version manifest fetch, update tab/promotion surface), #4107 perps
portfolio card, #4102 RabbySwap receiver check (removed product surfaces).

Customizations preserved: Hippo identity/branding, no Sentry init/DSN or
telemetry endpoint, CoW-only swaps via the order book, RPC policy (custom
wins; 1RPC → dRPC → PublicNode → 0xRPC; no relay), removed surfaces (Gas
Account sponsored submission, points/badges, perps, bridges, staking, faucets,
NFT trading, RabbySwap), consent-gated remote data. Approval lifecycle is
upstream-owned.

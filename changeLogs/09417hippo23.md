# v0.94.17-hippo.23 — Rabby v0.94.17 security line, 2026-11-27 backport

Selective security backport from RabbyHub/Rabby `develop` (range
99db35341..ca442b413, 35 commits inspected one by one in the daily run
`20261127T221700Z-daily`, evidence `daily-classification.md`). Rabby
v0.94.18 is not yet published as a stable release, so this release ports
the unreleased security fixes without merging unrelated `develop` work;
the weekly job owns the stable line when 0.94.18 ships.

Security fixes (ported as individual cherry-picks, `git cherry-pick -x`,
each gated by `yarn install --immutable` + `yarn check` before commit):

- #4302 (af3555a8e) — signing-path side effects and listener hygiene:
  hardware waiting screens (Common/Ledger/ImKey/Privatekey/Coinbase/
  WatchAddress) no longer leak `SIGN_FINISHED`/`TX_SUBMITTING`/
  `COMMON_HARDWARE.REJECTED` listeners across approvals — an unmounted
  earlier approval's handler can no longer run Gnosis signature/posting
  calls with the previous approval's params and a new signature;
  `useScopedEventBusListener` removes exactly the listeners it added and
  ignores post-unmount registrations. KeystoneWiredWaiting's render-time
  side effects are gone: each device response is decoded with a fresh
  URDecoder, request-id matched, and submitted at most once (the old
  shared decoder re-submitted its first result when the parent toggled
  the error message). The EIP-7702 reject-only gate moved above `SignTx`
  mount (`shouldBlockEIP7702Tx`, same origin/speed-up/revoke rules), so a
  refused request never mounts the signing page. Regressors:
  keystoneWiredWaiting, scopedEventBusListener, shouldBlockEIP7702Tx.
- #4303/#4304 (694443282, d95ec1442) — required companions of #4316:
  React key hazards in approval/connect/desktop tables fixed, mnemonic
  and hardware import components get guard components so no hook runs
  conditionally (private-key/mnemonic entry screens included).
- #4316 (2642d1a3d) — rules-of-hooks enforced in ESLint (error) and
  stale-response races dropped: `useAddressRisk` can no longer show the
  previous address's risk/CEX label or clear the forbidden-deposit
  warning when a late response lands after the input changed;
  GasSelectorHeader keeps estimate/base-fee in step with the signed
  price; token-info and keystone availability derived during render;
  TanStack-query resources read the UI wallet singleton and OpenAPI
  queries get their own helper. Regressors: openapiQuery, queryClient.
- #4315 (57ce0cfcb) — `ethRpc` fails closed on an unresolvable chain:
  the chain is resolved before the RPC cache is consulted, so a removed
  custom network or a not-yet-restored chain list can no longer be
  served from a cached result and can no longer crash on `findChain(...)!`
  (4902 "Unrecognized chain", zero probe/cache/RPC touched); the ready
  OpenAPI proxy no longer turns `toJSON`/symbol keys into API calls.
  Regressors: ethRpcUnknownChain (adapted to Hippo's RPC surface — see
  resolutions), openapiClient.
- #4344 (06d8639f4) — CI supply chain: `update-approvelist.yml` no
  longer interpolates the `workflow_dispatch` `json_url` input directly
  into a shell `run:` line (script-injection class); the value now flows
  through an env var and `curl --url`. Hippo ships this same workflow,
  which regenerates the in-app spender approve list.
- #4345 (42a5beafc) — background bootstrap survives corrupt stores: a
  missing/partial raw `rpc` store no longer bricks every restart, an
  enabled custom RPC is applied only when it is a string url (user
  custom still wins, unchanged), and a corrupt persisted MetaMask-mode
  site list is reset on init instead of throwing on every provider
  request. Regressors: customTestnetInit, metamaskModeService (Hippo
  variant).
- #4334 (1431149d4) — typed-data order views (swapTokenOrder, buyNFT,
  sellNFT, batchSellNFT) no longer crash the whole notification window
  when an EIP-712 domain has no `verifyingContract` (request was left
  neither resolved nor rejected); the contract-keyed block renders only
  when the address exists, so no security warning is hidden. Regressor:
  swapTokenOrderWithoutVerifyingContract.
- #4357 (7df4fbb2a) — upstream removed the reporting of raw EIP-712
  payloads to Sentry; validation/rejection is unchanged. Hippo ships no
  Sentry at all, so this ports as dead-code removal keeping the files
  aligned with upstream.

Hippo resolutions (divergences from a raw upstream pick, each disclosed):
- `controller.ts` ethRpc conflict resolved keeping Hippo's RPC policy:
  user custom RPC first, no Rabby probe fallback (`probeBestRPC` does
  not exist here), RpcCache keyed by `chainServerId:routingVersion`;
  upstream's fail-closed 4902 chain resolution applied on top. The
  ported test was adapted accordingly (own commit db59d1956): drops the
  `probeBestRPC` assertion, mocks `getRoutingVersion`.
- Removed products stay removed: the deleted-product files touched by
  #4303/#4304/#4316 (`Bridge/hooks/token.tsx`, `Perps/popup/
  WithdrawPopup.tsx`, `Perps/popup/SpotSwapPopup.tsx`, `RabbyPoints/
  index.tsx`, `Swap/hooks/token.tsx`, `Bridge/Component/BridgeQuotes.tsx`)
  were kept deleted; their hunks (stale HyperEVM fee guard, hook guards)
  are meaningless on absent surfaces. `AccountList.tsx` deletion taken
  as upstream proved it unreferenced (verified zero importers here).
- metamaskModeService: Hippo's removal of the remote
  `static.debank.com/fake_mm_dapps.json` fetch and its timers is
  preserved; only the corrupt-store guard from #4345 was adopted, and
  the upstream test was rewritten for the offline list (no http mock on
  purpose, documented in the test header).
- package.json/yarn.lock: only the two ESLint plugins from #4316 added,
  lock resolution additive-only (3e8720191); dependency security gates
  (age gate, enableScripts:false, preapproved scopes) untouched.
- New upstream docs under `skills/` (`rabby-data-fetching`) are carried
  as upstream developer documentation only; no Hippo contract change.

# v0.94.8-hippo.13 — Rabby v0.94.8 security line

This release integrates the RabbyHub/Rabby v0.94.8 stable line (14 commits) on top of the
v0.94.7 sync, carrying every Hippo customization and the eleven audited rounds of approval
hardening forward unchanged.

- Broadcast-chain pin (Rabby #4088): the chain a signed transaction is broadcast on is now
  pinned to the chain captured at approval time. A dApp calling
  `wallet_switchEthereumChain` while an approval window is open can no longer divert an
  already-signed transaction (including speed-up/cancel re-signatures) to an attacker-chosen
  network's RPC.
- Explorer-link protocol gate (Rabby #4087): explorer links built from remotely synced chain
  metadata are restricted to http(s); poisoned entries can no longer become
  `javascript:`/`data:`/`file:` navigations, and outbound explorer links carry
  `rel="noopener"`.
- Multi-action security acknowledgement (Rabby #4083): risk-rule acknowledgements are now
  scoped per action — accepting a warning on one action of a multi-action request no longer
  silently suppresses it on the others, and a blocked security result can no longer be
  bypassed by an alternate gas-payment method. Hippo's existing stricter approval-binding
  contract (exact id + component + epoch, background-only lineage, cancel-revokes-continuation)
  is preserved; the upstream boolean resolve/reject contract is adopted on top of it.
- Custom-network receipts (Rabby #4093): transaction receipt status on custom networks is
  read from the chain instead of being hard-coded to success, so a failed testnet
  transaction is no longer displayed as confirmed.
- Unchanged: CoW Swap remains the only swap surface; removed Rabby products (perps,
  bridges, Rabby Swap, gas account, points, staking, lending, NFT trading) remain removed;
  no Sentry transport, no security-rule telemetry, no installation identifier, no Rabby
  identity; user custom RPC stays first for replay-safe reads; signed transactions are
  never replayed across endpoints.

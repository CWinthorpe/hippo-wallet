Security fixes (verified applied, focused suites green):
- #4225 (10b25e9c6) — blocked-address refusal on every transaction signing
  path. `ethSendTransaction` now checks sender, receiver, token/NFT receivers
  embedded in calldata (transfer/transferFrom/ERC-721/1155 safeTransferFrom/
  safeBatchTransferFrom, plus Tempo call targets) and rejects before any
  keyring or hardware device is asked; mini sign checks alongside prepare
  context and refuses via a modal before the security engine runs (openUI and
  openDirect alike); SendNFT checks the receiver at selection.
  `approve`/`setApprovalForAll` are deliberately exempt so a blocked spender
  stays revokable. One shared background LRU cache (5 min/500 entries,
  in-flight dedup, failures never cached) backs all callers; a failed lookup
  fails open per address exactly like the existing SignTx behavior — and one
  address's failed lookup can never hide another already-known-blocked
  address. New regressors: blockedAddress.test.ts, blockedAddressSigning.test.ts.
- #4226 (871c4d077) — mini-sign signer-context substitution closed. The
  cached signer context (pre-exec results, security checks, and the exact
  txs that get signed) was keyed on chainId|to|value|data.length only, so a
  transaction differing in `from` or in same-length calldata (e.g. an
  ERC-20 transfer with a new recipient/amount) could reuse another tx's
  cached context. The fingerprint now covers `from` and full calldata.
- #4256 (3a619ad6f) — Keystone hardware signing companion fix: the new
  pre-sign blocked-address await made the QR waiting page's single on-mount
  pull miss the sign request, blanking QR and USB signing. The keyring now
  pushes each new sign request (MemStoreDataReady, wired once per singleton
  interaction), and SignTx routes its check through the background cache.
  Regressor: keystoneSignRequestPush.test.ts.
- #4224 (f6e3e4547) — dapp consent no longer survives chain removal:
  sites connected on a chain that leaves the supported list are persisted as
  disconnected on ETH and the dapp is notified with accountsChanged([])/
  chainChanged; startup waits for the cached chain list before evaluating
  site chains (no race against the bundled-only store); a chain list without
  ETH is rejected. Ported onto Hippo's no-remote-fetch syncChain stub:
  `disconnectSitesWithUnsupportedChain` lands verbatim for the live callers
  (permission bootstrap, custom-network removal); upstream's remote-fetch
  tests are adapted accordingly.
- #4245 (5cbe8e2a7) — screenshot feedback privacy: user addresses were
  attached to every feedback report without asking. Upload is now opt-in via
  a persisted, default-off checkbox; when off, addresses and tx hashes are
  masked inside pageUrl/routePath/currentScreen; device fingerprint hints
  (architecture, bitness, model client hints) are no longer collected.
  Hippo keeps its zero-Sentry/zero-analytics posture; the feedback surface
  remains the explicit user-initiated support path.
- #4229 (db1837c41) — supply chain: `enableScripts: false` in .yarnrc.yml,
  so no third-party dependency can run install scripts during
  `yarn install`, including on build machines holding registry tokens.
  Hippo's own gates (npmMinimalAgeGate 15d, preapproved-scopes list,
  patch-package postinstall) are preserved intact.
- #4243 (b93162f75) — custom-network signing: EIP-1559 detection from the
  chain's latest block; custom networks now sign type-2 transactions when
  both chain and keyring support them (no longer silently downgraded to
  legacy when maxFee == maxPriorityFee), while chains that fail detection
  keep the legacy fallback. A dapp-supplied maxPriorityFeePerGas is now
  preserved when the user re-selects the custom gas level. Regressors:
  customNetworkEip1559Signing.test.ts, customNetworkGas tests.
- #4242 (2135ade46) — dependency pins: @rabby-wallet/rabby-action 0.1.17,
  @rabby-wallet/rabby-security-engine 2.0.13 (manual reviewer danger
  verdicts now override automated trust scoring). Exact pins, lockfile
  checksums verified under immutable install.

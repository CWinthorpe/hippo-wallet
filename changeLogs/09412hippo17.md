# v0.94.12-hippo.17 — Rabby v0.94.12 security line

Ports the RabbyHub/Rabby v0.94.12 stable release (range a5f3af383..baf640e0a,
17 commits; develop head c3aed73f4 is the post-tag manifest-chore superseded by
Hippo's own versioning) with Hippo's privacy and product-surface invariants
preserved.

Security-relevant fixes:
- #4165 (587da9c57) hardens `eth_signTypedData` input in the background
  provider controller: typed-data JSON containing a `__proto__` key at any
  depth is rejected (a type hidden there is invisible to validation/display
  yet still resolved when signing via `Object.assign`), and `types` maps that
  redeclare a built-in EIP-712 name (`string`, `address`, `uint256`, …) are
  rejected (one implementation reads the struct, another reads the built-in,
  so what is shown may not be what is signed). New
  `src/background/utils/typedDataTypes.ts` + regressor
  `__tests__/background/typedDataTypes.test.ts` ported intact.
- #4166 (28af1d05c) stabilizes sequential signing approval windows:
  programmatic window removal is tracked per window id (a stale UI can no
  longer close a window the next request already reused), the background
  re-checks pending approvals before a self-close is honored
  (`closeNotificationWindow`), in-flight window creation is shared, and
  typed-data content now waits on an approval-scoped chain query so a stale
  response cannot replace the current approval's chain context.
  `notificationWindowLifecycle`, `sortHatNotification`, and
  `useApprovalBinding` regressors ported.
- #4174 (59d91b6d9) upstream removed the frontend sign-message origin
  fallback that synthesized a verify-address warning for unparsed messages
  containing other hosts' URLs. Ported faithfully (the module is deleted here
  too; backend-parsed origin checks and URL/address highlighting remain
  upstream-intact). This is an upstream behavior change, not a Hippo-side
  hardening addition or removal.
- #4159 (922c61cb3) surfaces WalletConnect clock skew instead of silently
  re-initializing the relay client (keyring patch: JWT "not yet valid"
  transport errors are classified and reported), centralizes
  transport-error handling in `reportWalletConnectTransportError`, and adds
  the user-visible clock-skew warning. Hippo resolution: the upstream
  Sentry-side throttling was NOT adopted (Hippo's Sentry config stays inert —
  no DSN, no ingestion; `getSentryConfig` untouched); classification,
  broadcast, and UI warning surfaces are ported fully.
- #4161 (6cb282529) HyperEVM (chain 999) gas limits now follow the sender's
  block mode (`eth_usingBigBlocks`): 3M small / 30M big blocks, falling back
  to the small-block cap when the query fails or is unsupported, instead of
  deriving the cap from an alternating `eth_getBlockByNumber` result.
  `calcGasLimit` shared with the approval/signing path; regressors ported.
- #4172 (e20330f86) IndexedDB opens lazily (perf/reliability of the first
  read, no eager open at every service-worker wakeup).

Also integrated: #4170 removed-tokens (user-side scam-token hiding; new
`removedTokens` persisted store — additive, no destructive migration,
existing upgraded profiles get the defaulted template), #4175 approved-spender
list data, i18n/changelog/docs, Least Authority audit PDF.

Nonported (Hippo removed surfaces — upstream changes to code that must not
exist here):
- #4144 OpenSea listing/accept-offer payload verification (#4144): Hippo has
  removed NFT marketplace/listing/trading entirely (no `src/utils/nft.ts`,
  no `@opensea/seaport-js` dependency, no listing modals). The upstream
  verification hardening could only land by restoring the removed surface,
  so it is deliberately not carried; the dependency stays out per the
  `privateBuildPrivacy` guard.
- #4120 bridge pending & history: bridge surface removed in Hippo; Bridge
  views/utils/tests and `@rabby-wallet/rabby-bridge` stay absent. The inert
  `BridgeTxHistoryItem` type shape and background history-service bookkeeping
  (#4120/#4167-adjacent cancellation fields) were ported where they only
  touch retained code. `src/ui/views/History/components/HistoryList.tsx` is
  kept at Hippo's version because upstream's only delta wires the removed
  Bridge history UI into the retained history list. Upstream's new
  bridge-history read accessors on the wallet controller and history
  service were dropped in the fix round (audit R17-B1): the UI-to-background
  dispatcher exposes every controller method dynamically, so a callable
  bridge-history accessor would be a live removed-product API surface even
  with no static caller. The privacy suite now pins both source files free
  of that accessor name.
- #4173/#4167 perps history fees: Perps surface removed; `src/utils/time.ts`
  cosmetic duration shortening retained (shared by approval queues), Perps
  files/tests not carried.
- #4158 `@rabby-wallet/rabby-bridge` 0.0.10→0.0.12: dependency stays removed.
- #4159's upstream regressor `__tests__/utils/walletconnect-sentry-rate-limit.test.ts`
  tests Sentry-ingestion throttling inside `getSentryConfig`. Hippo's Sentry
  config is inert by design (no DSN, `beforeSend` returns null — enforced by
  `privateBuildPrivacy`), so the telemetry-rate behavior it pins does not
  exist here. Test dropped as removed-surface; the security-relevant parts of
  #4159 (clock-skew classification, keyring patch, transport-error
  centralization, UI warning) remain fully pinned by
  `walletconnect-clock-skew`, `walletconnectTransportError`, and
  `walletConnectClockSkew` suites, all passing.
- #4161's regressor `__tests__/ui/sendTransactionHyperEvm.test.ts` adapted:
  upstream invoked `sendTransaction` with `isGasAccount`/`isGasLess` set,
  which Hippo's removed-surface guard rejects at entry. Flags narrowed to
  the ordinary send path; all HyperEVM gas-cap assertions (sender-mode
  queries, 12.45M/3M caps, preset-gas passthrough, no-mode-query checks)
  retained unchanged — 5/5 passing.
- #4178 SecSDK policy regeneration: regenerated for the Hippo module graph in
  the build commit instead of taking upstream's graph.

Hippo invariants re-proved on this build: name/branding (zero `Rabby Wallet`
runtime identity), inert telemetry (no Sentry DSN/init/ingestion, no
uninstalled reporting), CoW-direct order-book swap only (quote class
`priceQuality: 'verified'` behavior from hippo.15 intact, fail-closed
verified-gate preserved), single Hippo-owned WalletConnect project
configuration, RPC policy unchanged (user custom wins; replay-safe read
failover order; one-endpoint signed broadcast), removed products stay
removed (verified by the privacy suite and packaged runtime scans).
